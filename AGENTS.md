# Agent Guide

Guidance for AI agents and contributors working in this repository.

## What this is

`gh-runx` is a [GitHub CLI](https://cli.github.com) extension (invoked as
`gh runx`) that resolves a GitHub release, downloads the asset matching the
current platform, caches it, unpacks it, and execs the contained program.

## Commands

```sh
go build ./...     # build
go test ./...      # run tests
go vet ./...       # lint surface (no .golangci.yml)
gofmt -l .         # formatting check; must print nothing
```

Run the full pre-push set before pushing:

```sh
test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test ./...
```

Build and install the extension locally for manual testing:

```sh
go build -o gh-runx .
gh extension install .          # or copy gh-runx into the gh extensions dir
gh runx <org/repo>
```

## Architecture

The flow lives in `run` (`main.go`) and is split into focused packages:

- `internal/cli` — parse command-line arguments into `Options`. Handles flags
  on either side of the `org/repo` positional and `--` forwarding. Pure and
  fully unit-tested; keep it free of I/O.
- `internal/release` — look up a release via the GitHub REST API and select the
  asset matching `GOOS`/`GOARCH` (`MatchAsset`, with OS/arch aliases and
  skip-suffixes for checksums/signatures/packages).
- `internal/cache` — download an asset to the user config dir and reuse it; the
  `doer` seam matches the go-gh REST client's `Request` method.
- `internal/archive` — unpack `.tar.gz`/`.tgz`/`.zip` (or pass a bare binary
  through) and pick the executable to run. Extraction is atomic: it writes to a
  temp dir and renames into place, so a failed unpack leaves no partial tree.
- `internal/checksum` — when a release ships a SHA-256 sums manifest
  (`SHA256SUMS`, `checksums.txt`, …), verify the downloaded asset against it.
  Verification runs only on a fresh download, not on cache hits.
- `internal/runner` — replace the process via `syscall.Exec` on Unix; run a
  child process on Windows (`//go:build` split).

Asset downloads go through the GitHub asset API
(`repos/{owner}/{repo}/releases/assets/{id}` with
`Accept: application/octet-stream`) so private-repo releases work.

## Conventions

- **Go style** follows the workspace Go conventions: doc comments on all
  declarations (exported or not), alphabetized members, small focused packages,
  sentinel errors with the `Err` prefix, errors wrapped with context.
- **Tests** use external test packages (`package x_test`), `testify/require`
  for fatal assertions, one behavior per test function, and a
  `// ... verifies that ...` doc comment on each test.
- **No production code for test seams beyond what already exists** — prefer
  extracting pure logic (as `internal/cli` does) over mocking.
- **Commits** follow Conventional Commits. No attribution or "generated by"
  trailers.
- **PRs** merge via squash. Run the pre-push set first.

## Issue labels

Area labels map to packages: `area:release`, `area:cache`, `area:archive`,
`area:runner`, `area:cli`, plus `area:ci` and `area:docs`.
